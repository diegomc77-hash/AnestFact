Bookmarklets GECLISA — flujo por token

El marcador no lleva el DNI. Pide pegar el token que genera AnesFact y consume af_geclisa_consume_token en Supabase (HTTPS).

Producción (GitHub Pages)

Arrastrá este link a la barra de favoritos:

Rellenar GECLISA (token)

Carga fill.js desde Pages (HTTPS) — no choca con Private Network Access.

DEV — inline (recomendado para GECLISA http://)

Chrome bloquea http://GECLISA → http://localhost (Private Network Access). Este marcador lleva fill-dev.js embebido: no hace fetch a localhost al ejecutarlo. Solo habla con Supabase por HTTPS.

Abrí esta página desde http://localhost:8080/geclisa-bookmarklets.html, esperá “listo” y arrastrá:

Rellenar GECLISA DEV inline

Cargando fill-dev.js…

Si cambiás fill-dev.js, recargá esta página y re-arrastrá el favorito (el código queda congelado en el marcador).

DEV — fetch localhost (no usar desde GECLISA http)

Solo útil si el origen fuera HTTPS o mismo host. En Mayo (http://…:84) Chrome lo bloquea.

Rellenar GECLISA DEV (fetch)

Alternativa one-shot (consola)

  1. Abrí http://localhost:8080/fill-dev.js, copiá todo el archivo.
  2. En la foja GECLISA: F12 → Console → pegá → Enter.
  3. Pegá el token cuando lo pida.

Misma lógica que el inline; no hace falta favorito.

Prueba 008a

  1. AnesFact local → foja Mayo → Enviar a GECLISA → copiar token.
  2. GECLISA → foja paciente → clic DEV inline → pegar token.
  3. Confirmar relleno; el token no se reusa.
